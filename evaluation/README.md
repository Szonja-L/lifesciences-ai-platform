# evaluation/

Input data for measured evaluations. Results and write-ups go in [`docs/evaluation/`](../docs/evaluation/); this folder holds what those results are measured *on*.

What will live here (plan section 5.3):

| Subfolder (planned) | Contents | First used |
|---|---|---|
| `manifests/` | Synthetic batch of about 200 Track A submissions with planted, labelled errors, plus the label file saying which error sits in which cell | Month 5 (simulated baseline, plan section 8.5) |
| `papers/` | Hand-labelled Track B papers (`labels.jsonl`) | Weeks 6-7 |
| `qa/` | Question and answer pairs with reference evidence for Track B | Track B evaluation |
| `variants/` | Documented reference variant set for Track C annotation checks | Track C evaluation |

Rules:

- Synthetic or public data only. Every public source gets its licence and URL in a README next to it.
- Labels are never generated by the model being evaluated.
- A generated batch is reproducible: the script and seed that made it are committed, not just the output.
- Small unit-test fixtures do not belong here; they live in `tests/fixtures/`.
